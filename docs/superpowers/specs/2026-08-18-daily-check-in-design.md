# 每日打卡设计

## 目标

为“练记”增加一个每日打卡页面。用户在训练页勾选任意训练组后，系统自动记录当天的训练打卡；当天没有自动训练打卡时，用户可手动完成一次有氧打卡。页面以适合手机屏幕的月历展示历史，并按动作所属部位统计训练天数。

## 范围

- 在现有底部 Tab 中增加“每日打卡”入口和页面，不移除已有的动作预览入口。
- 根据训练页的“今日完成”训练组勾选状态维护当天自动训练打卡。
- 支持当天一次手动有氧打卡；有自动训练打卡时不能手动有氧打卡。
- 用可切换月份的月历展示打卡状态和本月统计。
- 在备份导入、导出与 Android SQLite / H5 本地存储降级中保留打卡数据。

不包含历史补打、修改过去的打卡、打卡提醒、云同步或按训练重量/次数统计训练量。

## 交互设计

### 打卡页

打卡页是新增的底部 Tab 入口。顶部显示当前月份，如“2026 年 8 月”，通过左右按钮切换月份。未来日期仅显示日期数字，不显示打卡状态，也不可操作。

月历按周一至周日排列。每个日期格显示日期；训练自动打卡用深绿色标记，有氧手动打卡用浅绿色标记，今天额外显示边框。格子尺寸随可用宽度均分，保证单屏手机能完整看到七列。日历下方说明两种颜色的含义。

今日操作区遵循以下状态：

| 当天状态 | 文案与操作 |
| --- | --- |
| 没有打卡 | 显示“有氧打卡”主按钮，点击后创建有氧打卡 |
| 有氧手动打卡 | 显示“今日已完成有氧打卡”，按钮不可重复提交 |
| 自动训练打卡 | 显示“今日已由训练自动打卡”，手动有氧按钮禁用 |

日历下方显示本月汇总：“已打卡 N 天 · 训练 N 天 · 有氧 N 天”，以及“本月部位训练天数”。部位统计按实际训练动作的目标部位显示，例如“胸 4 天 · 背 3 天 · 腿 2 天 · 有氧 1 天”。

### 自动训练打卡

训练页中任一动作的任一训练组被勾选为“今日完成”时，系统同步当天的打卡记录。自动打卡必须携带当天所有被勾选动作对应的去重部位列表。

- 同日勾选多个部位的动作，只产生一天训练打卡，但每个部位各增加一天训练天数。
- 同一部位的多个动作只计该部位一天。
- 取消一个动作的最后一个勾选，会从当天记录的部位列表移除该部位；同部位仍有其他被勾选动作时保留该部位。
- 取消当天全部训练组勾选，会删除当天的自动训练打卡；若该日原先是手动有氧打卡，则保留有氧打卡。
- 同日先手动有氧、后勾选训练组时，记录升级为自动训练打卡，来源改为 `training`，并保存训练部位；页面此后锁定手动有氧入口。

已有 `dailySetCheck` 只存储当天的临时勾选状态，并会在日期变化后失效。自动打卡同步必须在当天勾选变化时将结果持久化，月历历史不得从临时状态反推。

## 数据设计

新增逻辑表 `check_in`，在原生 SQLite 与 H5 降级存储中采用一致字段：

```js
{
  id: 'checkin-uuid-or-integer',
  checkDate: 'YYYY-MM-DD',
  source: 'training' | 'cardio',
  trainingParts: ['胸', '背'],
  cardioChecked: false
}
```

约束：每个 `checkDate` 最多一条记录；`source` 是展示用派生字段：`trainingParts` 非空时为 `training`，否则 `cardioChecked` 为真时为 `cardio`。`cardioChecked` 记录当天曾完成手动有氧，以便“先有氧、后训练、再取消全部训练”后恢复有氧打卡。SQLite 层将用日期唯一性实现覆盖式写入，H5 层按日期替换对应对象。

增加独立 `utils/checkIn.js`，负责纯数据规则：规范化记录、从已勾选动作生成部位集合、合并/升级自动训练记录、创建幂等有氧打卡、按月筛选记录与计算统计。页面和 SQLite 适配层通过该模块协作，不把规则散落在 Vue 组件中。

SQLite 适配层新增打卡记录的初始化、列表、按日读取、保存/删除和导出/导入支持。H5 的 fallback store 同步新增 `checkInRecords` 数组。导入旧备份时缺少该数组视为空数组；新备份带有该数据。

## 数据流

```text
训练页点击训练组完成圆圈
  -> dailySetCheck 更新今日临时状态
  -> 收集已勾选动作的 target
  -> checkIn 同步今日自动训练打卡
  -> SQLite / H5 持久化 check_in
  -> 打卡页 onShow 读取本月记录并重算统计

打卡页点击“有氧打卡”
  -> checkIn 创建今天 cardio 记录（训练记录存在时拒绝）
  -> SQLite / H5 持久化 check_in
  -> 刷新今日格与本月统计
```

## 错误处理

- 自动同步打卡失败不能阻止训练组勾选；训练页提示“打卡同步失败”，并在训练页 `onShow` 与打卡页 `onShow` 根据当前勾选状态再次同步今天。
- 手动有氧打卡前重新读取当天记录。若已是训练打卡，拒绝创建并刷新页面状态；若已是有氧打卡，直接返回现有记录。
- 无法加载月份记录时保留月份标题和空日历，并提示“打卡记录加载失败，请重试”。
- 解析导入数据时忽略日期格式、来源或部位格式非法的打卡项，其他合法数据继续导入；若整个备份结构不合法，沿用现有导入失败处理。

## 测试

- `utils/checkIn.test.cjs`：记录规范化、同日去重、手动有氧幂等、训练来源优先、取消训练后回退有氧、按月筛选、部位按天去重和汇总。
- `utils/sqlite.test.cjs`：SQLite/H5 fallback 的打卡增删查、同日期唯一性、导入旧备份兼容和导出包含打卡数据。
- `pages/train/index.test.cjs`：勾选/取消训练组触发当天自动打卡同步，并把已勾选动作的部位传入。
- `pages/checkin/index.test.cjs`：月历日期网格、未来日期限制、按钮状态和本月统计的展示数据。

## 验收标准

1. 当天勾选任一训练组后，打卡页当天显示训练自动打卡，且不能手动有氧打卡。
2. 没有自动训练打卡时，用户可仅为今天创建一次有氧打卡，重复操作不生成重复数据。
3. 先有氧后训练时，当天升级为训练自动打卡；取消全部训练勾选后回到当天有氧打卡。
4. 月历可切换月份，准确显示训练、有氧和未打卡日期，未来日期不会显示为已打卡。
5. 本月总天数、训练/有氧天数和各部位训练天数正确；同部位一天多动作只算一天。
6. Android SQLite、H5 fallback、导入与导出均能保存和恢复打卡记录；旧备份可正常导入。
