# 全量动作目录与逐组训练记录设计规格

日期：2026-07-29

## 目标

同时升级 `app-local/` 和 `app-api/`：

1. 将原始数据集中所有有效动作纳入动作库，不再只保留胸、肩、背、腿、有氧五类。
2. 对缺少中文动作名的记录，通过可配置的 OpenAI 兼容大模型接口进行健身语境翻译；密钥只在本地数据生成脚本中使用，不进入 App。
3. 将训练记录从单个固定重量/组数/次数升级为每组独立记录重量和次数，并兼容已经保存的旧记录。

当前数据证据：原始数据共 1324 条、19 个目标部位；所有记录都有 `id`、`media_id` 和 `instructions.zh`，1324 条都缺少 `name_zh`。

## 数据生成设计

清洗脚本仍输出原有五个字段：

```text
id, name_zh, target, media_id, instructions_zh
```

但 `target` 改为覆盖全部 19 个目标部位的中文标签，例如 `abs -> 腹部`、`biceps -> 肱二头肌`、`pectorals -> 胸`、`cardiovascular system -> 有氧`。原始记录只要五个必需字段有效就保留，重复 `id` 仍只保留第一条。

动作名翻译使用独立的可恢复脚本或清洗脚本中的翻译模块，调用 OpenAI 兼容的 `POST /chat/completions` 接口。配置来自环境变量：

```text
TRANSLATION_API_BASE_URL
TRANSLATION_API_KEY
TRANSLATION_MODEL
```

不在源码中写入密钥，不在 App 运行时调用翻译 API。脚本使用严格的健身翻译提示词，要求返回简体中文动作名，不添加解释，不把器械、姿势、方向和侧别丢失。翻译结果按原始动作 `id` 缓存到本地未跟踪缓存；支持批量请求、失败重试和中断后继续。缺少 API 配置或翻译失败时脚本停止并报告具体 id，不使用现有的词典拼接或未经确认的机器直译兜底。

最终生成：

- `static/json/clean_fitness_zh.json`
- `data/clean_fitness_zh.js`

两份输出字段和内容一致，目标数量应为全部有效记录。现有的动作教程中文字段直接复用，不重复调用翻译模型。

## 分类展示设计

训练页不再写死五个分类。动作目录加载后动态计算分类顺序：

1. `全部`
2. 常用分类：胸、肩、背、腿、有氧
3. 其余按数据首次出现顺序排列

分类条可以横向滚动，动作选择弹窗的搜索仍按 `name_zh` 过滤，并同时受当前分类过滤。点击“全部”时，添加动作必须保留数据自身的 `target`，不能把分类覆盖成“全部”。

## 逐组训练记录设计

一条 `train_record` 继续代表某个动作的一次训练记录，并增加 JSON 字段 `setDetailsJson`：

```json
[
  { "setNo": 1, "weight": 40, "reps": 12 },
  { "setNo": 2, "weight": 45, "reps": 10 }
]
```

字段约束：

- 至少 1 组；
- `setNo` 从 1 开始连续编号；
- `weight` 为大于等于 0 的数字，单位 kg；
- `reps` 为正整数；
- 保存时以数组长度作为组数。

为兼容已有 Android SQLite 数据，初始化时执行一次幂等的 `ALTER TABLE train_record ADD COLUMN setDetailsJson TEXT`，已存在该列时忽略错误。旧记录没有该字段时，根据原有 `weight`、`sets`、`reps` 合成重复的组明细，例如旧记录 40 kg、4 组、10 次会转换为四条 40 kg × 10 次。H5 本地存储同样在读取时兼容旧格式。

写入时保留旧字段用于兼容旧数据和旧查询，但新记录的真实数据以 `setDetailsJson` 为准。更新记录时整体替换组明细，删除动作时继续删除对应训练记录。

## 录入界面设计

训练弹窗改为动态组列表：

- 默认打开 4 组；
- 每行显示“第 N 组”、重量输入框、次数输入框；
- 支持“添加一组”和删除某组；
- 编辑已有记录时回填每组的重量和次数；
- 保存前逐行校验，错误时明确指出第几组；
- 卡片摘要显示组数和各组概况，例如“4 组 · 40×12 / 45×10 / 45×8 / 50×6”。

本地版和联网版的页面、组件、SQLite/H5 降级逻辑保持一致，避免两个版本功能分叉。

## 测试与验收

数据侧：

- 目标部位 19 类全部可映射；
- 缺失中文名时必须走翻译接口，翻译失败不会静默生成英文或拼接词典结果；
- 生成 JSON 为 UTF-8，字段严格为五个字段；
- 输出记录数量等于全部有效去重记录；
- 翻译缓存可以让第二次运行不重复调用 API。

训练侧：

- 新增 4 组不同重量/次数后重新打开仍保持原值；
- 可添加和删除组，删除后编号连续；
- 旧的固定重量/组数/次数记录读取后显示为重复的组明细；
- Android SQLite 和 H5 本地存储测试都通过；
- 两个版本的 JavaScript 语法检查和既有测试全部通过。
